# 生成代码审查清单（P1）

用于评审 AI 生成的收钱吧接入代码是否满足最小可上线标准。

## A. 架构与边界

- [ ] 是否按 `protocol / adapter / support / bootstrap` 分层？
- [ ] 是否把收钱吧字段隔离在接入层，而非业务核心域？
- [ ] 前端是否未直接使用 `terminal_key`、签名、验签逻辑？

## B. 支付正确性

- [ ] 是否做了三层状态判定（`result_code` → `biz_response.result_code` → `order_status`）？
- [ ] 非最终状态是否接入轮询？
- [ ] `client_sn` 是否保证全局唯一？

## C. 安全性

- [ ] 是否复用共享签名模块（无重复内联签名实现）？
- [ ] 回调是否强制 RSA SHA256WithRSA 验签？
- [ ] 验签失败是否拒绝处理且记录日志？

## D. 幂等与补偿

- [ ] 回调是否有幂等去重（`sn` 或 `client_sn`）？
- [ ] 重复通知是否不会重复执行业务动作？
- [ ] 轮询超时后是否有明确人工兜底路径？

## E. 运行与运维

- [ ] 是否显式保留“无沙盒环境”警告？
- [ ] 是否提供关键日志字段（`client_sn`、`terminal_sn`、`order_status`、错误码）？
- [ ] 是否有最小可执行验证命令与测试说明？

---

评审结论建议：
- 全部通过：可进入联调/灰度；
- 存在 A/B/C 任一不通过：禁止上线；
- 仅 D/E 缺陷：需附整改计划和截止时间。
